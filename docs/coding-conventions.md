# コーディング規約メモ

厳密な規約集ではなく、このプロジェクトで作業するときに揃えておくべき方向性をまとめます。

## 基本方針

- まず既存の書き方に合わせる
- 小さい変更で済むなら、無理に大改修しない
- 責務が増えすぎたら分割を検討する

## ファイルの触り方

- `GameScene` 周辺は影響範囲が大きいので、一度に広げすぎない
- 再利用する配置物は `prefab` 化を優先する
- 試作段階の一時コードをそのまま本番運用にしない

## 命名

- ゲーム上の意味があるものは、見た目より役割で名前を付ける
- たとえば `Flame` より `Hot` のように、将来の拡張がしやすい抽象名を優先する
- `enabled`、`defeated`、`frozen` のような状態名は意味を分けて使う

## 状態追加

- 新しい挙動を足すときは、元オブジェクト側とコピー側の両方を見る
- 単に色を変えるだけでなく、接触や復元処理まで確認する
- リトライ時に戻るべき状態かどうかを考える

## 描画

- グリッド基準の見た目を崩さない
- 選択中状態や危険状態は色だけで分かるようにする
- デバッグ表示を増やしたら、邪魔になりすぎないかも見る

## データとコード

- 何度も使うものは JSON 側へ寄せる
- 1 回しか使わない検証はコード直書きでもよい
- ただし、コード直書きとデータ定義の二重管理は避ける

## コミット前

- 不要な生成物を含めない
- 実装を変えたら関連ドキュメントも更新する
- 入力、描画、挙動の 3 つが揃っているか確認する
