# シェーダ担当ガイド

このガイドは、シェーダや画面演出を触る担当者向けです。

## まず知っておくこと

- このプロジェクトは DxLib ベースで動いています
- シェーダは見た目だけでなく、ビルド成果物や `.cso` の扱いでも競合しやすいです
- 画面演出を変えるときは、実装だけでなく生成物の扱いも意識します

## まず見るファイル

- `shader.cpp`
- `shader.h`
- `game_scene_render.cpp`
- `shader_showcase_scene.cpp`
- `DirectXFoundation.vcxproj`

## よくある作業

### 画面エフェクトの見た目を調整する

- まず `game_scene_render.cpp` でどこから使われているかを見る
- 次に対象シェーダの読み込みや適用位置を確認する
- 実際の見た目確認は `ShaderShowcase` や該当シーンで行う

### 新しいシェーダを追加する

1. シェーダ本体を追加する
2. 読み込みや適用コードを `shader.cpp` 側に足す
3. 必要ならシーン側で呼び出す
4. 生成物の扱いを確認する
5. Git に何を含めるかを決める

## 注意点

### `.cso` は競合しやすい

- バイナリなので GitHub 上で解決しにくいです
- 触る前に、その生成物を管理する必要があるか考えます
- 詳しくは `docs/git-and-artifacts-guide.md` を見ます

### 見た目だけで完了にしない

- パフォーマンス低下がないか
- `Title`、`Game`、`Result` のどこに効くか
- UI やデバッグ表示を壊していないか

### シェーダ変更はスクリーンショットだけで判断しない

- 実際のプレイ中に読めるか
- フィルター UI やグリッド表示とケンカしていないか
- 一時的な演出なのか、常時表示なのかを区別する

## フィルターとの関係

現在のゲームでは `Hot / Cold / Invert / Sepia` が重要です。

- 撮影枠の色
- 画面の薄い色味
- 写真コピーの見た目

を変える場合は、フィルター仕様と整合しているか確認します。

## 作業前チェック

- どのシーンで確認するか決めたか
- `.cso` を含めるのかを決めたか
- 既存エフェクトと重複していないか見たか

## 作業後チェック

- 画面が読みにくくなっていないか
- 低スペック環境で重くなりすぎていないか
- merge 時にバイナリ競合しそうなものを増やしていないか
